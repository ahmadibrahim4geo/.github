Also consider marking code-only experimental repositories clearly as **Development Preview** in their README and Releases. Missing license detection in GitHub does not justify guessing a project-wide license: audit third-party obligations first.

## Recommended community hygiene

- Use a standard MIT/LICENSE only for repositories where the owner has confirmed ownership and intended MIT publication.
- Use contributor guides, bug forms, security contact, changelogs and tested CI where appropriate.
- Never require every repository to use a single platform/framework or enforce one commercial software host.
- Keep personal portfolio content aligned with descriptions in individual project READMEs.
